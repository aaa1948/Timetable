# SCENE — 팀 촬영 플래너

팀 프로젝트의 **촬영 장소와 팀원별 불가능한 시간**을 모으고, 모두 가능한 시간을 찾는 한국어 웹 앱입니다. 초대 링크로 같은 팀 공간에 접속하며, 사진을 포함한 데이터를 서버에 저장합니다. 새로고침하거나 브라우저를 닫아도 데이터가 유지됩니다.

## 기능

- **팀 공간**: 프로젝트 이름으로 생성, 초대 링크 복사. 링크를 받은 팀원들이 각자의 기기에서 같은 정보를 조회·수정합니다. 5초마다 자동 동기화하고 탭으로 돌아올 때도 갱신합니다.
- **촬영 장소**: 등록자 이름, 장소 이름, 주소/검색어, 메모, 사진 등록·수정·삭제. 각 장소 아래 네이버 지도·카카오맵 검색 링크, 그 아래 첨부 사진을 보여 줍니다. 사진은 JPG/PNG/WebP, 파일당 2MB 이하이며 팀당 최대 40개 장소를 등록합니다.
- **팀원**: 추가할 인원수를 입력하고 인원수만큼 이름을 입력합니다. 팀당 최대 30명, 중복 이름은 구분해서 입력합니다. 팀원을 삭제하면 해당 일정도 삭제됩니다.
- **불가능한 시간**: 이름 → 요일 → 시작/종료 → 이유 순서로 입력합니다. 한 사람이 여러 일정을 입력할 수 있습니다. 월~일을 가로축, 00:00~24:00을 세로축으로 1시간씩 표시합니다. 칸을 누르면 해당 시간의 이름과 이유가 나옵니다. 개인별 보기와 일정 삭제를 지원합니다.
- **모두 가능한 시간**: 불가능한 일정들의 합집합을 제외한 시간을 계산하여 요일별 연속 구간으로 안내합니다. 모든 팀원이 ‘일정 입력 완료’를 눌러야 공통 가능 시간을 확정 표시합니다. 일정이 없더라도 완료 버튼을 눌러야 하며 미입력 팀원은 ‘확인 전’입니다.
- **저장**: 브라우저 localStorage가 아닌 Supabase 데이터베이스 또는 Node 서버 파일 저장. 서로 다른 팀원의 동시 입력은 서버에서 순차 반영하며 저장 오류를 화면에 알립니다.
- **반응형**: 작은 화면에서는 입력 폼을 위쪽에 배치하고 시간표는 가로·세로 스크롤을 지원합니다.

## GitHub Pages + Supabase 연결 (권장)

접속 주소: **https://aaa1948.github.io/Timetable/**

GitHub Pages는 화면 파일을 제공하고 Supabase는 공유 데이터를 저장합니다. 서버를 직접 운영할 필요가 없습니다. 아래 최초 설정이 끝나야 팀 공간 생성·공유가 활성화됩니다. 설정 전에는 안내문을 표시하고 생성 버튼을 비활성화합니다.

1. [Supabase](https://supabase.com/dashboard)에서 본인 계정으로 프로젝트를 생성합니다.
2. 프로젝트의 **SQL Editor → New query**에서 [`supabase/setup.sql`](supabase/setup.sql) 전체를 붙여넣고 실행합니다.
3. 프로젝트의 **Connect** 또는 **Settings → API Keys**에서 Project URL과 공개 **Publishable key** (`sb_publishable_...`, 또는 기존 `anon` 키)를 확인합니다. `secret` / `service_role` 키는 사용하지 마세요.
4. [`public/config.js`](public/config.js)의 `SUPABASE_URL`, `SUPABASE_KEY`에 위 값을 입력하고 커밋합니다. `API_BASE`는 빈 문자열로 둡니다. 공개 키는 브라우저용이며 팀 코드와 테이블 접근 제한으로 팀 데이터를 보호합니다.
5. GitHub 저장소 **Settings → Pages → Build and deployment → Source → GitHub Actions**를 선택합니다. **Actions → Deploy GitHub Pages → Run workflow**를 실행하거나 main에 커밋하면 `public/`을 배포합니다.
6. 배포 완료 후 위 주소에서 팀 공간을 만들고 초대 링크를 전달합니다. 두 기기에서 일정을 입력하고 새로고침하여 사진·일정이 유지되는지 확인합니다.

**대체 배포:** Source를 **Deploy from a branch**, Branch를 **main / (root)**로 설정해도 루트 `index.html`이 같은 화면을 제공합니다. `public/index.html`을 수정했다면 `node scripts/pages-root.mjs`로 루트 화면을 갱신하세요. Actions 방식은 `public/index.html`을 직접 사용합니다.

**Supabase 저장 구조:** 팀별 JSON(사진 포함)을 DB에 보관합니다. 테이블 직접 조회·수정은 차단하고, 무작위 팀 코드를 아는 요청만 전용 함수로 조회·수정합니다. 저장 시 버전 확인과 행 잠금을 사용하고 충돌 시 최신 데이터를 읽어 재시도합니다. 링크를 아는 사람은 공동 편집자이며 개인별 권한·링크 회수는 없습니다. 사진이 많으면 DB 용량·통신량이 늘어납니다. 소규모 팀용이며 공개 서비스에는 로그인·생성 요청 제한·사진 전용 저장소를 추가하세요. Supabase 요금·용량·프로젝트 중지 정책은 본인 계정에서 확인하세요. 기존 Node 서버 데이터는 자동 이관되지 않습니다.

**1시간 단위 변경:** 새 일정은 정각에 시작·종료하며 00:00~24:00의 24개 행으로 표시됩니다. 내부 저장 형식은 기존 30분 슬롯을 유지합니다. 기존 09:30~10:30 일정은 원래 시간을 보존하며 09~10시와 10~11시 모두 불가능으로 표시합니다.

## 로컬 Node 서버 실행

Node.js **22 이상**이 필요합니다. 외부 npm 패키지나 API 키는 필요하지 않습니다.

```sh
git clone https://github.com/aaa1948/Timetable.git
cd Timetable
npm start
```

브라우저에서 `http://localhost:3000`에 접속합니다. PowerShell에서 npm 실행 정책 오류가 발생하면 `npm.cmd start` 또는 `node server.js`를 사용하세요.

1. 프로젝트 이름을 입력해 팀 공간을 생성합니다.
2. 추가할 인원수와 각 팀원의 이름을 입력합니다.
3. 이름을 선택하고 불가능한 시간과 이유를 저장한 뒤 ‘일정 입력 완료’를 누릅니다.
4. 초대 링크를 팀원에게 전달하고 각자 일정을 입력합니다.
5. 모두 입력을 마치면 시간표와 ‘함께 가능한 시간’에서 공통 시간을 확인합니다.
6. ‘촬영 장소’ 탭에서 장소와 사진을 등록합니다.

**일정 기준:** 한국 시간(KST), 날짜가 없는 매주 반복 시간표입니다. 종료 시간은 포함하지 않습니다. 예를 들어 09:00~10:00은 09:00~10:00 칸을 막고 10:00부터는 비어 있습니다. 자정을 넘는 일정은 `월 23:00~24:00`, `화 00:00~01:00`처럼 나누세요. 가능 시간은 입력된 불가능한 일정만을 기준으로 합니다.

## 팀원들과 접속하기 / 배포

`localhost`는 자기 컴퓨터 주소이므로 이 주소의 링크를 다른 사람에게 보내도 접속할 수 없습니다.

- **같은 Wi-Fi/LAN**: 서버 컴퓨터의 내부 IP(예: `http://192.168.0.10:3000`)로 접속한 뒤 그 주소에서 초대 링크를 복사합니다. 서버 컴퓨터가 켜져 있어야 하며 방화벽에서 해당 포트 연결이 허용되어야 합니다.
- **외부 인터넷**: Node.js 또는 Docker를 실행할 수 있는 서버에 배포하고 HTTPS 도메인을 연결합니다. `DATA_DIR`에 영구 디스크/볼륨을 반드시 연결하세요. 앱의 서버는 하나만 실행합니다.
- **GitHub Pages에서 공유 저장:** 위 Supabase 연결 절차를 사용하세요. 기존 Node 서버를 따로 배포했다면 `public/config.js`의 `API_BASE`를 해당 HTTPS 주소로 설정할 수도 있습니다. Node 서버는 기본으로 `https://aaa1948.github.io` 요청을 허용하며 `ALLOWED_ORIGINS` 환경 변수(쉼표 구분)로 변경할 수 있습니다.

Docker 실행 예시:

```sh
docker build -t scene-timetable .
docker run -d --name scene-timetable --restart unless-stopped -p 3000:3000 -v scene-data:/data scene-timetable
```

| 환경 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | `3000` | HTTP 포트 |
| `HOST` | `0.0.0.0` | 바인딩 주소 |
| `DATA_DIR` | 프로젝트의 `data/` | 팀 데이터와 사진을 저장하는 경로 |

Docker에서는 `DATA_DIR=/data`로 설정되어 있습니다. 일반 실행에서 다른 경로를 쓰려면 PowerShell에서 `$env:DATA_DIR='D:\scene-data'`를 설정한 후 실행하세요.

## Node 서버의 공유 및 데이터 관리

- 초대 링크는 128비트 무작위 팀 코드가 들어 있는 **공동 편집 권한 링크**입니다. 링크를 아는 사람은 해당 팀의 모든 정보를 조회·추가·삭제할 수 있습니다. 개인 계정, 팀원별 권한, 링크 만료/회수 기능은 없습니다. 신뢰하는 팀원에게만 공유하세요.
- 팀 코드는 URL의 `#room=...`에 넣어 일반 페이지 요청과 외부 지도 링크의 리퍼러에 포함되지 않도록 했습니다. API에는 팀 코드가 사용되므로 운영 서버에서 API 경로 로그의 접근 권한도 관리하세요.
- 사진은 팀별 JSON 파일 안에 이미지 데이터로 저장됩니다. 런타임의 `data/`는 Git에서 제외되어 있습니다. 서버 재시작 후에도 같은 디렉터리를 사용하면 복원됩니다. 서버의 임시 디스크가 초기화되면 사라지므로 **영구 볼륨과 백업**이 필요합니다.
- 백업: 서버를 잠시 정지한 뒤 `DATA_DIR` 전체를 복사합니다. 복원: 서버를 정지하고 백업을 같은 경로에 복원한 뒤 재시작합니다. 링크도 따로 보관하세요.
- 소규모 팀용 단일 프로세스 파일 저장 구조입니다. 다중 서버/프로세스 운영, 대규모 공개 서비스에는 데이터베이스·오브젝트 스토리지·인증·요청 제한 등을 추가해야 합니다. 같은 항목을 동시에 수정하면 서버가 마지막으로 처리한 작업을 반영합니다.
- 사진을 많이 등록하면 초기 로딩과 동기화 데이터가 커집니다. 필요한 해상도로 줄여 등록하는 것을 권장합니다.

## 개발 및 검증

```sh
npm test
```

Node 내장 테스트 도구로 공통 시간 계산(겹침·경계·자정), 동시 입력 보존, 중복 이름/잘못된 시간 검증, 사진 저장, 서버 재시작 복원, 팀원 삭제 시 일정 정리, 다른 출처의 변경 요청 차단을 검사합니다. 테스트는 임시 디렉터리를 사용하므로 실제 팀 데이터를 변경하지 않습니다.

```text
public/index.html   한국어 화면 및 폼
public/style.css    반응형 스타일
public/app.js       폼, 시간표, 사진, 팀 공유 및 동기화
public/schedule.js  공통 시간 계산
server.js           HTTP API, 입력 검증, 파일 저장
test/app.test.js    계산 및 API 통합 테스트
Dockerfile         영구 볼륨을 사용하는 배포 이미지
```

지도는 장소 이름과 주소로 생성한 검색 링크이며 좌표 검증·장소 예약·촬영 허가 확인 기능은 포함하지 않습니다.

검증 범위: Node API 통합 테스트와 시간 계산, Supabase 클라이언트의 충돌 재시도를 자동 검사합니다. Supabase SQL과 실제 두 기기 간 동기화는 프로젝트 연결 후 별도로 확인해야 합니다.

## 여러 시간 선택 / 장소 수정

- 이름을 선택하고 **시간표에서 여러 시간 선택**을 켠 뒤 원하는 1시간 칸을 여러 개 누릅니다. 다시 누르면 선택이 해제됩니다. 또는 요일·시작·종료를 정하고 **이 시간대를 선택에 추가**를 눌러 여러 구간을 모을 수 있습니다.
- 선택 요약을 확인하고 공통 이유를 입력한 뒤 **선택한 시간 저장**을 누르면 한 번에 저장됩니다. 연속된 칸은 하나의 일정으로 묶이며, 실패하면 선택이 유지됩니다. 선택이 없고 다중 선택 모드가 꺼져 있으면 기존처럼 입력한 단일 구간을 저장합니다.
- 장소 카드의 **수정**을 눌러 등록자·장소 이름·주소·메모를 변경할 수 있습니다. 사진을 새로 선택하지 않으면 기존 사진을 유지하며, 새 파일로 교체하거나 **사진 제거**로 지울 수 있습니다. **수정 취소**는 저장하지 않고 입력을 초기화합니다.
- 기존 Supabase 함수와 호환됩니다. SQL을 다시 실행하거나 연결 설정을 바꿀 필요가 없습니다.

## 장소 지도와 학교 위치

촬영 장소 탭의 목록 아래에 OpenStreetMap 지도가 표시됩니다. 촬영 장소는 초록색, 학교는 주황색이며 **전체 보기**로 저장된 모든 좌표를 한 화면에 표시합니다. 마커를 누르면 이름·주소·메모와 위치 수정 버튼이 나옵니다.

- 등록 폼의 **장소 종류 → 학교**를 선택하면 학교도 같은 방법으로 등록·수정·삭제할 수 있습니다.
- **지도에서 위치 지정**을 누른 뒤 지도를 확대·이동하고 위치를 클릭합니다. **이 위치 저장**으로 폼에 적용한 후 **장소 저장**을 눌러 등록합니다. 위도·경도를 직접 입력해 지정할 수도 있습니다.
- 이전 장소에는 좌표가 없으므로 지도 위의 **장소 이름 · 위치 지정**을 눌러 최초 한 번 위치를 저장하세요. 지정되지 않은 항목은 지도에 임의로 표시하지 않고 별도 목록과 개수로 안내합니다. 주소 변경 시 좌표는 다시 지정합니다.
- 주소 자동 검색은 제공하지 않습니다. 별도 API 키 없이 지도 클릭으로 정확한 위치를 저장하는 방식입니다. 좌표와 종류는 기존 locations 항목에 저장되므로 Supabase SQL 재실행이 필요 없습니다. 학교도 기존 최대 40개 장소 제한에 포함됩니다.
- 지도는 Leaflet 1.9.4와 OpenStreetMap 타일을 사용하며 인터넷 연결이 필요합니다. 저작자 표시는 지도 하단에 표시하고 타일을 일괄 다운로드하거나 오프라인 저장하지 않습니다. [타일 이용 정책](https://operations.osmfoundation.org/policies/tiles/)을 준수해야 합니다.
